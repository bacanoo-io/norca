# Norca

**Project status: alpha.** The design, the documentation and the implementation are not final and may change.

> [!WARNING]
> **Written with AI coding agents.** Most Norca-specific code was generated by
> AI coding agents from written design and implementation specs.
> Human review covered: the maintainer's own specifications and the revised
> designs made from them, the test and lab results, the summaries before each
> merge, and part of the generated code.
> CI runs the licence checks, builds for Linux and Windows, `go vet` and the
> unit tests that need neither root nor Docker, Consul or Vault. The
> integration suites do not run in CI (see [CONTRIBUTING.md](CONTRIBUTING.md)).

> Keep this in mind when evaluating fit for your environment.

An independent, open source workload scheduler and orchestrator built on the HashiCorp Nomad v1.6.5 source code (MPL 2.0), with its own extensions: a built-in autoscaler, namespace quotas, admission policies, backup and restore, service discovery without Consul, package management and a new web UI.

> [!IMPORTANT]
> **Norca is not a drop-in replacement for Nomad.** It started from the Nomad v1.6.5 source and keeps the Nomad 1.6.5 HTTP API, so API clients and tools built against that API can talk to it. Everything else is Norca's own: the binary and CLI are `norca`, the environment variables are `NORCA_*` (also the ones injected into workloads), job files use the `.norca.hcl` suffix, the built-in DNS and the TLS and mTLS names use the `.norca` domain, and the many additions change behaviour and configuration. An existing Nomad cluster, its job files, certificates and configuration cannot be switched to Norca without changes, and Norca makes no promise of compatibility with future Nomad releases.

## Usage

Norca is a single binary, `norca`, which runs both the agent and the CLI. Build it from the `norca/` directory (Go module `github.com/bacanoo-io/norca/norca`):

```shell
cd norca
make dev                  # writes bin/norca and copies it to $GOBIN
# or: go build -o norca .
```

```shell
norca agent -dev          # start a development agent
norca job init            # write an example job file
norca job run example.norca.hcl
norca version             # Norca v0.3.0 (Nomad API 1.6.5 compatible)
```

The version line shows the Norca version and the Nomad version whose HTTP API Norca is compatible with. API clients and tools built against that API keep working against it.

Step-by-step deployment examples (development agent, single node, three nodes, multi region): [example/](example/README.md).

### Packages

`norca rigger` is Rigger, the package manager of Norca; the standalone `rigger` program has the same commands. It installs modules (packages written in typed HCL) and stacks (several modules with their values) as releases, with versions, registries, a lock file and signatures. The operations modules (NATS, the cross-region mTLS gateway, RustFS as the backup store, Consul, the LoadBalancer operator) live in the [Norca registry](https://github.com/bacanoo-io/norca-registry), and the [global registry](https://github.com/bacanoo-io/norca-global-registry) lists them as `norca/<name>`. A stack names a module by that source:

```hcl
# stack.hcl
rigger {
  name = "platform"
}

module "bus" {
  source  = "norca/nats"
  version = "~> 2.0"
}
```

```shell
norca rigger stack sync .                      # resolve the versions, fetch and verify the modules, write rigger.lock.hcl
norca rigger stack apply .                     # install the releases of the stack
norca rigger install ./my-module -name web     # one release of a module in a directory
```

See [rigger/README.md](rigger/README.md), the language by example in [rigger/examples/](rigger/examples/README.md), and the [deployment examples](example/README.md#the-module-registry).

The `consul` module installs the official Consul release, which this project does not distribute. Consul is licensed under BSL 1.1, which you accept at install. If you offer Norca with Consul to third parties as a service, check the BSL Additional Use Grant yourself.

### Running scripts written for the Nomad CLI

A copy of the binary, or a symlink to it, named `nomad` (`nomad.exe` on Windows) behaves exactly like `norca`, so scripts written for the Nomad 1.6.5 CLI keep working. No such alias is shipped or installed; create it yourself if you need it, for example `ln -s "$(command -v norca)" /usr/local/bin/nomad`. Help and usage texts always say `norca`.

### Environment variables

The CLI and the API client read their settings from `NORCA_*` environment variables:

| Variable | Meaning |
| --- | --- |
| `NORCA_ADDR` | Address of the HTTP API, default `http://127.0.0.1:4646` |
| `NORCA_TOKEN` | ACL token secret ID |
| `NORCA_REGION` | Region to forward requests to |
| `NORCA_NAMESPACE` | Target namespace |
| `NORCA_HTTP_AUTH` | HTTP basic auth, `user:password` |
| `NORCA_CACERT`, `NORCA_CAPATH` | CA certificate file or directory |
| `NORCA_CLIENT_CERT`, `NORCA_CLIENT_KEY` | Client certificate and key for mTLS |
| `NORCA_TLS_SERVER_NAME` | SNI server name |
| `NORCA_SKIP_VERIFY` | Skip TLS verification |
| `NORCA_CLI_NO_COLOR`, `NORCA_CLI_FORCE_COLOR` | Disable or force colored output |

Command-line flags take precedence. The variables injected into workloads (`NORCA_ALLOC_ID`, `NORCA_TASK_DIR`, ...) and the jobspec variable prefix `NORCA_VAR_` use the same prefix.

`norca rigger` talks to the cluster of `NORCA_ADDR` and `NORCA_TOKEN` and reads its own settings from `RIGGER_*` variables: `RIGGER_VAR_<name>` (the value of a variable), `RIGGER_SERVER` (the servers evaluate), and `RIGGER_GIT_*` and `RIGGER_OCI_*` (the credentials of git and OCI sources). See `norca rigger help` and [rigger/README.md](rigger/README.md).

## Security

Norca starts from Nomad v1.6.5 (December 2023). Fixes that HashiCorp released only in later, BSL-licensed versions are not inherited. Where Norca fixes the same problem, the fix is written independently from the public issue and changelog description (see [CONTRIBUTING.md](CONTRIBUTING.md)). Do not assume that a vulnerability fixed in a later Nomad release is fixed in Norca unless the Norca release notes say so.

Report vulnerabilities privately through the repository (Security, "Report a vulnerability"); see [SECURITY.md](SECURITY.md).
